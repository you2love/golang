Lint 工具 - Go 代码检查

Lint 工具用于检查 Go 代码中的潜在问题、风格问题和性能问题。使用 lint 工具可以提高代码质量，保持代码风格一致性。

golangci-lint

安装

# 使用 go install (推荐)
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest

# 使用 Homebrew (macOS)
brew install golangci-lint

# 使用 Scoop (Windows)
scoop install golangci-lint

快速开始

📝 基本使用

# 运行所有 linter
golangci-lint run

# 运行特定 linter
golangci-lint run --enable=gofmt,govet,errcheck

# 自动修复问题
golangci-lint run --fix

# 输出为 JSON 格式
golangci-lint run --out-format=json

# 显示 linter 执行时间
golangci-lint run --show-stats

# 只检查新代码 (相对于 git)
golangci-lint run --new-from-rev=HEAD~1

配置文件

📝 .golangci.yml 配置

# .golangci.yml
run:
  # 超时时间
  timeout: 5m
  # 要检查的目录
  tests: true
  # 跳过目录
  skip-dirs:
    - vendor
    - testdata

linters:
  # 禁用所有默认 linter
  disable-all: true
  # 启用特定 linter
  enable:
    - gofmt
    - govet
    - errcheck
    - staticcheck
    - unused
    - gosimple
    - structcheck
    - varcheck
    - ineffassign
    - deadcode
    - typecheck
    - gosec
    - unconvert
    - goconst
    - gocyclo
    - dupl
    - misspell
    - unparam
    - prealloc
    - exportloopref
    - exhaustive
    - nakedret
    - copyloopvar

linters-settings:
  # govet 配置
  govet:
    check-shadowing: true
    enable-all: true
    disable:
      - fieldalignment
  
  # gocyclo 配置
  gocyclo:
    min-complexity: 15
  
  # dupl 配置
  dupl:
    threshold: 100
  
  # goconst 配置
  goconst:
    min-len: 2
    min-occurrences: 3
  
  # misspell 配置
  misspell:
    locale: US
  
  # gocritic 配置
  gocritic:
    enabled-tags:
      - diagnostic
      - experimental
      - opinionated
      - performance
      - style
    disabled-checks:
      - whyNoLint

issues:
  # 最大问题数量
  max-issues-per-linter: 0
  max-same-issues: 0
  # 排除规则
  exclude-rules:
    # 排除测试文件中的某些检查
    - path: _test\.go
      linters:
        - errcheck
        - gosec
    # 排除生成的代码
    - path: \.pb\.go
      linters:
        - all
  # 使用默认排除规则
  exclude-use-default: false

output:
  # 输出格式
  formats:
    - format: colored-line-number

常用 Linter

📖 Linter 说明

Linter 说明 示例
gofmt 代码格式化 缩进、空格
govet 可疑代码检查 printf 参数、shadow
errcheck 错误检查 未处理的 error
staticcheck 高级静态分析 废弃 API、无效代码
unused 未使用代码 未使用的变量、函数
gosimple 简化建议 可简化的代码
ineffassign 无效赋值 无意义的赋值
gocyclo 圈复杂度 复杂度过高
dupl 重复代码 代码克隆
misspell 拼写检查 英文拼写错误
gosec 安全检查 安全漏洞
prealloc 预分配建议 slice 预分配

CI/CD 集成

GitHub Actions

📝 GitHub Actions 配置

# .github/workflows/lint.yml
name: Lint

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  golangci:
    name: lint
    runs-on: ubuntu-latest
    steps:
      # 检出代码
      - uses: actions/checkout@v3
      
      # 设置 Go 环境
      - uses: actions/setup-go@v4
        with:
          go-version: '1.21'
          cache: false
      
      # 运行 golangci-lint
      - name: golangci-lint
        uses: golangci/golangci-lint-action@v3
        with:
          version: latest
          args: --timeout=5m
          only-new-issues: true

Git Pre-commit Hook

📝 Pre-commit 配置

# .pre-commit-config.yaml
repos:
  # Go 代码检查
  - repo: https://github.com/golangci/golangci-lint
    rev: v1.54.2
    hooks:
      - id: golangci-lint
        args: [--timeout=5m]
  
  # Go 代码格式化
  - repo: local
    hooks:
      - id: gofmt
        name: gofmt
        entry: gofmt
        args: ['-w']
        language: system
        types: [go]
  
  # Go 模块整理
  - repo: local
    hooks:
      - id: go-mod-tidy
        name: go mod tidy
        entry: go mod tidy
        language: system
        types: [go]
        pass_filenames: false

staticcheck

安装和使用

# 安装
go install honnef.co/go/tools/cmd/staticcheck@latest

# 运行检查
staticcheck ./...

# 指定检查规则
staticcheck -checks=all,-ST1000 ./...

# 输出为 JSON
staticcheck -f json ./...

检查规则分类

分类 前缀 说明
通用错误 S1xxx 常见错误和反模式
性能 S2xxx 性能问题
代码风格 S3xxx 代码风格问题
简化建议 S4xxx 可简化的代码
废弃 API SAxxxx 使用废弃的 API
构建标签 STxxxx 构建标签问题

revive

安装和配置

# 安装
go install github.com/mgechev/revive@latest

# 运行
revive ./...

# 使用配置文件
revive -config revive.toml ./...

# 指定 formatter
revive -formatter friendly ./...

最佳实践

✅ Lint 使用建议

  • CI 集成: 在 CI/CD 中自动运行 lint 检查
  • Pre-commit: 使用 pre-commit hook 在提交前检查
  • 渐进式: 老项目逐步启用更多 linter
  • 配置统一: 团队使用统一的 lint 配置
  • 自动修复: 使用 --fix 自动修复可修复的问题
  • 定期更新: 定期更新 linter 版本获取新规则

⚠️ 注意事项

  • 不要过度配置: 启用过多 linter 会降低效率
  • 忽略规则: 合理使用 nolint 注释
  • 性能考虑: 大项目注意超时设置
  • 误报处理: 对于误报添加排除规则
